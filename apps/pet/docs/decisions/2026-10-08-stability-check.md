## 재현한 결함과 수정

### 초기화가 진행 중인 입력·정리와 겹침

기존 초기화는 세 스케줄러의 실행 여부만 확인했다. 실제 SQLite에서 자동 정리와 쓰기가 대기 중이거나 즉시 AI 추출이 응답을 기다리는 동안에도 초기화가 200으로 성공했다(예상은 409). `/ingest`는 본문 저장 이후의 분류 후처리에서도 보호가 끝나, 초기화와 겹치면 참조 무결성 오류가 재현됐다.

- 기존 DB별 쓰기 큐를 재사용해 실행·대기 중 변경을 검사한다.
- 잠금 밖 AI 준비부터 저장 완료까지 활동 수를 추적한다. AI 호출을 직렬화하지 않고 중첩 호출·실패에서도 `finally`로 해제한다.
- REST/MCP 텍스트 저장, 덧붙이기·from-text, 수동 정리, `/ingest` 전체 후처리, 수동 이미지 재임베딩에 적용한다.
- 초기화 검사는 동기 DB 초기화 직전에 하므로 검사와 삭제 사이에 다른 비동기 작업이 끼어들지 않는다. 작업 중이면 409로 거절하며 기존 데이터는 그대로 남는다.

주요 파일: `apps/memory/src/memory/shared-memory-mutation-lock.ts`, `src/server-internal/{save-input,shared-memory-write}.ts`, `src/server-internal/routes/{cleanup,ingest,memories-append,memories-from-text}.ts`.

### 종료 요청이 끝난 서비스를 다시 실행함

트레이가 실행 중인 서비스를 찾은 뒤 그 서비스가 끝나면, `Bridge::request`가 종료 요청을 보내려고 새 서비스를 띄웠다. 실제 Windows Bun 프로세스로 중단 순서를 고정한 회귀 테스트 2개가 수정 전에 실패했다.

`service.drain`만 자동 시작을 하지 않도록 변경했다. 일반 요청의 재시작 동작과 기존 세대별 요청 검사는 유지한다. 종료된 서비스·한 번도 시작하지 않은 서비스에서는 새 프로세스가 생기지 않고, 실행 중인 실제 서비스는 정상적으로 drain에 응답한다.

주요 파일: `apps/pet/src-tauri/src/bridge.rs`, `src-tauri/src/bridge/tests.rs`.

## 테스트 환경과 종료 검증

- 이전 Windows 실패 29개는 테스트용 심볼릭 링크 권한 오류였다. Windows에서는 junction을 쓰되 링크 밖 파일 보존·링크 제외 검사는 그대로 유지했다. 권한을 높이거나 검사를 생략하지 않았다.
- 디스크 부족 검사는 사용자 기본 포트 대신 임시 포트를 사용한다. 실제 임시 HTTP 서버로 기존 서버 감지 시 쓰기 전에 거절하는 경우도 검사한다. 제품의 기본 탐지 포트는 바뀌지 않았다.
- 실제 `main.ts` 서비스와 제어 가능한 오프라인 명령 fixture로 백업 대기 중·화면 이탈 후 백업·검증·복원 종료를 검사했다. drain 응답 전에 자식 PID 종료, 기존 파일 보존, 임시 백업 정리, 복원 취소 기록, 종료 이후 새 요청 거절을 확인했다.
- 위 종료 fixture의 DB 파일은 바이트 보존용 표식이다. 실제 SQLite 스냅샷·백업 내보내기·첨부 포함 복원은 별도의 실제 코어 명령 통합 검사로 확인했다. 복원 통합 검사는 보관된 기억을 사용하므로 활성 기억 전체의 모델 재계산 성능까지 증명하지 않는다.
