# Bara System Pet 제품 방향과 설치·사용 설계 초안

작성일: 2026-09-24

이 문서는 최초 합의를 남긴 기록입니다. 이후 구현과 사용자가 추가한 작은 입력줄·말풍선 방향은 [현재 진행 상황](../status.md)과 [사용 안내](../user-guide.md)를 따릅니다.

상태: 대화에서 합의한 제품 방향을 기록한 설계 초안. 구현 사양과 출시 순서는 아직 확정하지 않았다. 문서의 제안과 미결정 사항을 사용자 결정으로 취급하지 않는다.

## 1. 목적

사용자는 대시보드를 열면 각 잡고 기록하거나 검색해야 하는 느낌을 받는다. 작은 펫을 곁에 두고 간단히 입력하거나 질문하면 사용 부담이 줄어들기를 원한다. 캐릭터의 목적은 사용자가 만만하게 느끼는 입구를 만드는 것이다.

사용자의 핵심 요구:

> 비개발자가 exe 파일 하나로 설치하고 사용할 수 있기를 바란다.

여기서 설치 성공은 프로그램 파일을 복사한 상태로 끝나지 않는다. 사용자가 첫 메모를 실제로 저장하고 다시 찾아볼 수 있는 상태까지 준비되어야 한다.

## 2. 대화에서 확인된 요구

- 작은 데스크탑 펫을 기본 입구로 삼는다.
- `입력하기`와 `질문하기`를 구분한다.
- 입력은 가볍게 받고, 가능한 분류는 AI가 보조한다.
- 질문하면 메모리를 검색해서 답하거나 관련 내용을 뷰어로 보여준다.
- Windows 로그인 시 자동 실행을 지원한다.
- 메모리 서버와 MCP(모델이 기억 도구를 사용하는 연결 규약)의 연결 준비를 앱이 챙긴다.
- PC에서 이용 가능한 로컬 AI를 답변에 활용할 수 있게 한다.
- 연동 가능한 고성능 AI를 메모리 정리에 활용할 수 있게 한다.
- 바라 서버는 내 PC 또는 A1 같은 외부 서버에 설치할 수 있다.
- 하나의 Windows 설치 파일에서 펫을 PC에 설치하고, 외부 서버 설치도 안내·진행할 수 있게 한다.
- 펫 저장소는 `mua-vtuber/Bara_System_Pet`, 메모리 서버 저장소는 `mua-vtuber/Bara_System`이다.

## 3. 제품 경계

| 담당 | 책임 |
|---|---|
| 펫 앱 | 캐릭터, 입력·질문 화면, 로그인 자동 실행, 서버 연결, PC의 AI 연결, 뷰어 열기 |
| 설치·준비 기능 | 로컬 설치, 외부 서버 설치, 기존 서버 연결, 준비 상태 확인, 중단된 설치 재시도 |
| 바라 서버 | 원문 저장, 검색, 추출, 분류 결과 검증, 정리 제안과 승인 정책, 데이터 관리 |

펫은 서버의 공개 API(프로그램 간 요청 통로)와 MCP를 사용한다. 서버 DB를 직접 열거나 내부 소스 파일을 가져다 쓰지 않는다. 서버에 필요한 새 기능은 바라 저장소의 변경으로 분리하고, 펫에는 같은 메모리 엔진을 복제하지 않는다.

별도 저장소여도 사용자에게는 설치 파일 하나로 배포할 수 있다. 두 제품의 버전 호환성과 설치 가능한 조합은 명시적으로 관리해야 한다. 분리의 대가는 두 저장소를 함께 검증해야 한다는 점이다.

## 4. 설치 경험 제안

### 4.1 이 컴퓨터에 설치

1. 펫과 바라 서버 실행에 필요한 구성 요소를 준비한다.
2. AI 사용 여부와 이용할 연결을 선택한다.
3. 메모리 서버를 실행하고 실제 준비 상태를 확인한다.
4. 펫의 인증·서버 연결을 설정하고 첫 입력 화면을 연다.

일반 사용자가 Git, Bun, Python, WSL 등을 직접 설치하거나 명령어를 입력하는 절차는 제품의 완료 조건을 충족하지 못한다. 필요한 실행 환경을 함께 제공할지 자동 설치할지는 기술 검증 후 결정한다. 모든 모델을 설치 파일 안에 넣는다는 뜻은 아니다.

### 4.2 내 외부 서버에 설치

1. 이미 생성된 서버의 주소, 계정, SSH(원격 접속) 키를 지정한다.
2. 접속, 운영체제, CPU, 설치 권한, 기존 바라 설치 여부를 확인한다.
3. 대상 서버에서 지원하는 실행 환경과 바라 서버를 설치한다.
4. 서버 부팅 시 자동으로 실행되도록 서비스를 등록한다.
5. 펫이 사용할 인증과 연결을 준비하고 실제 접속을 확인한다.

Windows 설치 프로그램이 원격 작업을 진행하고, 서버에서는 해당 Linux·CPU 환경에 맞는 프로그램이 실행된다. 첫 지원 환경을 A1에서 사용하는 Ubuntu ARM64로 한정하는 방안을 제안한다. 지원 OS·버전은 아직 확정하지 않았다.

클라우드 계정 가입과 인스턴스 생성은 이 경로의 선행 조건이다. 설치 프로그램이 새 클라우드 자원을 만드는 기능은 별도 결정 사항이다.

SSH 접속에서는 서버 신원 확인을 생략하지 않는다. 기존 설치와 데이터가 발견되면 새 설치로 덮어쓰지 않고 기존 서버 연결 또는 명시적인 업그레이드 흐름으로 전환한다. 중단된 작업은 완료된 단계를 확인한 뒤 재시도할 수 있어야 한다.

### 4.3 이미 사용하는 바라에 연결

펫만 설치하고 기존 서버의 연결 정보와 인증을 등록한다. 서버 재설치나 데이터 이동을 요구하지 않는다. 현재 사용자의 A1은 이 경로에 해당한다.

바라의 기존 SSH 터널 접근 방식을 첫 연결 방식으로 활용하는 것을 제안한다. 설치용 SSH 권한과 일상 사용용 메모리 접근 권한을 구분하고, 비밀값을 로그·설정 내보내기·오류 화면에 노출하지 않는다.

### 4.4 설치 파일과 다운로드

권장안은 작은 설치 파일이 필요한 실행 환경과 모델을 인터넷에서 내려받는 방식이다. 비개발자는 별도 사이트 방문이나 터미널 입력 없이 설치 화면 안에서 준비를 끝낸다.

인터넷 없이 설치해야 하는지 여부는 사용자 확인 중이다. 완전한 오프라인 설치는 파일 크기와 모델 배포 방식이 달라지므로 같은 요구로 취급하지 않는다. 내려받을 배포물의 버전과 무결성을 검증하는 방법은 구현 설계에서 정한다.

## 5. 평소 사용 경험 제안

### 입력하기

한 줄을 입력하고 보내면 실제 저장 결과를 확인해 짧게 알려준다. 태그·중요도·프로젝트를 필수 입력으로 요구하지 않는다. 초안과 실패한 입력을 보존하고, 저장이 확인되지 않은 내용을 저장 성공으로 표시하지 않는다.

### 질문하기

질문은 기본적으로 새 기억 저장 명령과 구분한다. 관련 기억을 검색하고 답변 AI가 이용 가능하면 근거에 따라 답한다. 원문 열기 버튼으로 해당 기억을 보여준다. 근거가 부족하면 그 사실을 알리고 기억 내용을 만들어내지 않는다.

답변 AI가 없거나 연결되지 않았을 때는 검색 결과와 원문을 보여주는 흐름을 제안한다. 이 경우 답변이 생성된 것처럼 표시하지 않는다.

### 자동 실행과 연결

로그인 자동 실행을 설정할 수 있게 한다. 실행 시에는 사용자가 선택한 서버에 연결하고, 앱이 관리하는 로컬 서버인 경우 실행을 준비한다. 필요할 때 연결 상태와 재시도 방법을 알려주되 일상 입력 화면에 개발 용어를 늘어놓지 않는다.

무거운 모델을 언제 실행하고 해제할지는 아직 결정하지 않았다. 펫 상주가 모든 AI의 상시 실행을 의미하지는 않는다. 앱 종료와 원격 메모리 서버 종료도 별도 동작으로 다룬다.

## 6. AI 역할과 자동 분류

기억을 저장하는 장소와 AI를 실행하는 장소는 독립적으로 설정한다. A1에 기억을 보관하면서 PC의 AI를 활용할 수 있도록 설계한다. PC가 꺼지면 PC의 AI가 담당하는 작업은 실행할 수 없으며, 이를 원격 서버 작업 성공으로 표시하지 않는다.

| 역할 | 제안 |
|---|---|
| 질문 답변 | 연결된 로컬 모델 또는 사용자가 선택한 답변 AI |
| 짧은 입력 분류 | 바라의 기존 기준과 사용자가 지정한 정보를 사용해 보조 |
| 깊은 메모리 정리 | 연동 가능한 고성능 AI로 기존 정리 도구 실행 |

PC에 AI 앱이 설치되어 있다는 사실만으로 앱이 호출할 수 있다고 가정하지 않는다. 실제 연동 통로, 인증, 실행 방식은 지원 대상마다 확인한다. 구독이나 로그인만으로 모든 호출이 가능한 것으로 표시하지 않는다.

자동 분류의 제안 원칙:

- 사용자 원문을 보존하고 AI 분류를 수정 가능한 정보로 다룬다.
- 사용자가 명시한 분류와 프로젝트를 AI 추정보다 우선한다.
- 바라의 분류 어휘와 검증 규칙을 공유한다.
- 애매한 입력은 억지로 할 일·결정·프로젝트로 확정하지 않는다.
- 분류가 느리거나 실패해도 기록을 받아둘 수 있는 흐름을 목표로 한다. 서버의 기존 입력 검증과 저장 정책은 유지한다.
- 매번 확인창을 요구하지 않고, 분류 결과를 간단히 알리며 수정할 수 있게 한다.

현재 바라의 추출 유형과 사용자가 보는 `아이디어`, `할 일` 같은 분류는 동일하지 않다. 사용자용 분류 목록, 적용 시점, PC와 서버 중 실제 분류를 수행할 주체는 아직 결정하지 않았다.

정리용 AI를 연결해도 바라 서버의 제안 검증·승인 경계를 우회하지 않는다. 필요한 검토는 기존 뷰어 또는 대시보드의 대상 내용으로 연결한다.

## 7. 현재 확인된 기반과 추가 작업

2026-09-24에 바라 저장소 `4839919d`의 소스와 해당 작업 공간의 로컬 참고 문서를 확인했다. 로컬 문서 일부는 Git에 포함되어 있지 않다. 이 확인은 원격 운영 서버의 배포 상태를 보증하지 않는다.

| 확인된 기반 | 추가로 필요한 일 |
|---|---|
| `apps/launcher`의 Tauri 기반 설치·실행 UI | 펫 화면, 입력·질문, 로그인 자동 실행, 원격 서버 연결 경험 |
| `apps/setup/src/engine.ts`의 로컬·서버 준비 모드 | Windows에서 SSH로 외부 설치를 끝내는 실행·복구 흐름 |
| `infra/a1/README.md`와 `deploy/`의 운영 설치 절차 | 사용자·경로·지원 환경 설정, 기존 설치 탐지, 설치 진행 표시 |
| MCP 검색·원문 조회와 기존 대시보드 뷰어 | 답변 실행, 근거 연결, 특정 기억을 여는 연결 약속 검증 |
| 일반 메모 원문 저장·추출과 명시 태그 활용 | 짧은 입력에 대한 분류 품질 검증, 사용자용 분류 경험 |

펫 저장소에는 문서만 있으며 제품 코드·설치 파일은 없다. 기존 런처를 그대로 배포하면 위 요구가 모두 충족되는 상태는 아니다.

## 8. 완료를 판단할 사용자 시나리오

아래는 목표 검증 항목이며, 아직 통과한 테스트가 아니다.

1. 개발 도구가 없는 Windows PC에서 설치 파일 하나로 로컬 설치를 마치고 실제 메모를 저장·검색한다.
2. 지원 대상의 빈 외부 서버에 PC 설치 화면만으로 바라를 설치하고, 펫에서 저장·검색한다.
3. 기존 바라에 연결할 때 서버 재설치와 기존 데이터 변경이 발생하지 않는다.
4. 설치가 끊긴 뒤 다시 실행하면 완료된 단계와 실제 설치 상태를 확인해 이어서 준비한다.
5. Windows 재로그인 뒤 자동 실행 설정에 맞게 펫과 연결이 복구된다.
6. 짧은 입력·오타·모호한 지시어로 분류를 평가하고, 잘못된 분류를 수정할 수 있다.
7. 서버 또는 AI 연결이 실패하면 초안을 보존하고 실제 상태와 재시도 방법을 보여준다.
8. AI 답변에서 근거 원문을 열 수 있고, 검색 결과가 없을 때 기억을 만들어내지 않는다.
9. 고성능 AI의 정리 결과가 바라의 기존 검증·승인 절차를 통과한다.

## 9. 구현 전 정할 사항

- 설치 중 인터넷 다운로드 허용 여부와 다운로드 용량 안내.
- Windows 지원 버전과 외부 서버 지원 OS·버전.
- 기존 Tauri 런처 활용 여부와 펫 렌더링 방식. 새 프레임워크·의존성은 미확정.
- 첫 지원 AI 연결 대상, 인증 방식, 답변·정리 실행 주체.
- 사용자용 분류 목록과 실제 입력으로 평가할 기준.
- 원문 뷰어를 앱에 표시할지 브라우저로 열지 여부.
- 설치·업데이트 배포물, 호환 버전, 코드 서명 방식.
- 기능별 개발 순서와 첫 배포에 포함할 기능. 본 문서는 요구를 임의로 축소하지 않는다.

## 10. 근거
