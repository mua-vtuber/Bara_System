# 비개발자를 위한 바라 설치·연결·트레이 운영 설계

작성: 2026-10-04 · 상태: 사용자 요구사항을 반영한 검토안 · 구현은 시작하지 않음

## 1. 목표와 확정한 결정

개발 도구, 포트 번호, 인증 토큰, 설정 파일을 몰라도 바라를 설치하고 기억을 남기거나 찾을 수 있게 한다. 사용자는 바라가 실행 중인지 펫 또는 트레이 아이콘으로 알 수 있고, 화면에 캐릭터를 계속 둘 필요는 없다.

| ID | 사용자 확정 요구사항 |
|---|---|
| U1 | 펫과 앱이 설치한 로컬 메모리 서버를 하나의 앱으로 취급한다. 독립 메모리 서비스·데몬을 만들지 않는다. |
| U2 | 펫 숨기기를 제공한다. 숨겨도 메모리 기능은 유지하고 트레이가 앱의 접근점과 실행 표시가 된다. |
| U3 | 트레이 아이콘을 누르면 입력·검색·대시보드·설정 메뉴가 나온다. |
| U4 | 켜져 있는지 알 수 있어야 하지만, 표시가 눈에 거슬리지 않아야 한다. |
| U5 | 숨김 상태에서는 사용자가 직접 요청한 결과만 작은 말풍선으로 표시한다. |
| U6 | 로컬 설치, 기존 서버 연결, MCP 등록, AI 선택, SSH 준비, 선택적 Discord 연결의 자동화를 계획에 포함한다. |
| U7 | 이번 작업은 계획 작성이다. 코드 구현·설치·설정 변경·서비스 가동은 하지 않는다. |
| U8 | 업데이트는 기존 버전을 확인하고 프로그램의 추가·교체·폐기 파일을 처리하되, 사용자 데이터와 설정을 보존한다. 필요한 데이터 변환과 실패 복구도 계획에 포함한다. |
| U9 | 제거는 프로그램만 제거하는 경우와 이 PC의 데이터를 함께 제거하는 경우를 구분한다. 앱이 만든 등록·실행 흔적을 정리하고, 외부 서버 데이터와 다른 프로그램은 보호한다. |

아래의 세부 기본값과 기술 설계는 위 요구사항을 구현하기 위한 제안이다. 현재 구현과 구분하여 읽는다.

## 2. 사용자가 경험할 흐름

1. 설치 파일을 실행한다.
2. **기억을 어디에 보관할까요?** — `이 컴퓨터` / `사용 중인 바라` / `내 외부 서버에 새로 설치`.
3. 선택한 경로의 준비를 진행한다. 경로·포트·필수 모델·인증정보는 앱이 처리하고, 계정 로그인·서버 신뢰 확인 등 사람이 결정할 항목만 요청한다.
4. **어디에서 사용할까요?** — 펫은 기본, AI 앱 연결과 Discord는 선택. 선택 기능은 나중에 설정할 수 있다.
5. 답변 AI가 발견되면 프로그램과 모델을 목록에서 선택한다. 없어도 기억 저장·검색으로 먼저 시작한다.
6. 연결 검사 결과와 사용 방법을 보여준다. `펫으로 보기` / `트레이로만 사용`을 선택하고 끝낸다.

완료 화면은 저장소·답변 AI·정리 AI·선택한 외부 연결의 결과를 따로 표시한다. AI 설정 저장, AI 프로그램 실행 여부, 모델 연결 성공은 서로 다른 상태다. 선택하지 않은 기능은 실패가 아니라 `나중에 연결`로 표시한다.

기존 설치가 발견되면 이 초기 설정을 무조건 다시 실행하지 않는다. 설치된 버전과 데이터 호환성을 확인해 `업데이트` 또는 `같은 버전 복구`로 안내하고, 제거 시에는 보존할 데이터 범위를 먼저 선택한다(4.7–4.8절).

## 3. 한 앱의 수명과 화면 상태

| 상태 | 펫 | 트레이 | 앱 소유 로컬 서버 | 사용자가 할 수 있는 일 |
|---|---|---|---|---|
| 준비 중 | 선택에 따라 표시 | 준비 중 표시 | 준비 단계에 따라 가동 | 진행 확인·중단·재시도 |
| 펫 모드 | 표시 | 표시 | 유지 | 펫 또는 트레이로 모든 기능 사용 |
| 트레이 모드 | 숨김 | 표시 | 유지 | 트레이에서 입력·검색·대시보드·설정 사용 |
| 주의 필요 | 모드 유지 | 조용한 상태 표시 | 실제 상태를 반영 | 메뉴의 상태 설명·복구 조작 |
| 종료 중 | 닫기 진행 | 종료 중 표시 | 진행 요청 정리 후 종료 | 종료 진행 확인 |
| 종료 | 없음 | 없음 | 종료 | 다시 바라를 실행해야 사용 가능 |

- **펫 숨김은 앱 종료가 아니다.** 작성 중인 입력창이나 사용자가 연 설정 창을 임의로 닫지 않는다. 입력 초안은 유지한다.
- 큰 창의 X는 해당 창을 닫는다. 앱 전체 종료는 명확히 `바라 종료`로 구분한다.
- 로그인 시 자동 실행도 바라 앱 전체를 시작한다. 메모리 서버만 따로 자동 실행하지 않는다.
- 마지막 펫/트레이 모드를 복원한다. 처음 설치할 때는 펫 표시가 기본이다.
- 트레이 생성에 실패하면 숨김 상태로 성공 처리하지 않는다. 펫이나 복구 창을 보여주고 실패 원인을 알린다.
- Windows가 아이콘을 넘침 영역으로 옮길 수 있다. 앱이 강제로 작업 표시줄 고정을 보장한다고 쓰지 않는다. 첫 숨김 때 아이콘 위치와 Windows의 표시 설정을 짧게 안내한다.
- 실행 여부는 앱 프로세스의 실제 상태로 표시한다. 연결 상태는 마지막 확인 시점을 함께 알리고, 오래된 성공을 현재 연결 보장으로 표현하지 않는다. 상태를 위해 AI 모델을 주기적으로 호출하거나 고빈도 네트워크 검사를 추가하지 않는다.
- **소유권 경계:** 바라가 띄운 로컬 서버·SSH 터널·선택적 봇 자식만 종료한다. 기존 A1 서버, 별도로 실행한 메모리 서버, 사용자가 실행한 Ollama/LM Studio 등은 중단하지 않는다. 외부 서버 연결에서는 바라 쪽 연결과 UI가 함께 끝난다.

### 3.1 트레이 메뉴

왼쪽 클릭과 오른쪽 클릭 모두 아래 메뉴를 연다. 메뉴를 열면서 큰 창도 함께 띄우지 않으며, 마우스 누름·놓음으로 명령을 두 번 실행하지 않는다.

```text
바라 실행 중 · 연결됨       ← 상태 설명, 실행 명령 아님
─────────────────────
입력
검색
대시보드
설정
최근 결과
─────────────────────
펫 숨기기 / 펫 보이기      ← 현재 모드에 따라 한 가지 표시
바라 종료
```

- `입력`: 작은 입력창을 열고 초점을 준다. 이미 열려 있으면 다시 초점만 준다. 캐릭터 클릭의 열기/닫기 토글을 그대로 호출하지 않는다.
- `검색`: 현재 작은 입력창의 질문 흐름을 연다. 기억을 찾고, 답변 AI가 설정되어 있으면 근거가 있는 답변도 제공한다. 질문 자체는 저장하지 않는다. 별도의 새 검색 엔진을 만드는 범위는 아니다.
- `대시보드`: 현재 연결에 맞는 인증정보를 네이티브 내부에서 사용해 브라우저를 연다.
- `설정`: 설치·연결·AI·외부 앱·표시 모드를 관리하는 화면을 연다.
- `최근 결과`: 자동으로 뜨지 않았거나 사라진 결과를 사용자가 직접 다시 연다.

### 3.2 숨김 상태의 입력창·말풍선·사용량

- 펫이 보이면 지금처럼 펫 근처에 입력창과 결과를 배치한다.
- 숨겼다면 클릭한 트레이 위치가 속한 모니터의 작업 영역을 기준으로 배치한다. 트레이 위치를 얻지 못하면 최근 사용자 조작이 있던 모니터, 마지막으로 주 모니터 작업 영역을 사용한다. 보이지 않는 펫의 옛 좌표에 의존하지 않는다.
- 위치는 사용자가 메뉴를 실행한 시점에 확인한다. 이를 위해 항상 동작하는 전역 마우스 감시기를 추가하지 않는다.
- 직접 실행한 저장·검색·정리·연결 확인의 결과는 작은 말풍선으로 잠시 표시한다. 숨긴 펫을 결과 때문에 다시 나타나게 하지 않는다.
- 주기적 진단·자동 재연결·백그라운드 유지 작업은 말풍선을 띄우지 않는다. 주의가 필요하면 트레이 상태와 최근 결과에 남긴다. 반복 깜빡임·소리·자동 큰 창 열기는 기본 동작에 넣지 않는다.
- 결과의 원인은 앱이 요청을 시작할 때 기록한다. AI 답변이나 서버의 문구를 보고 사용자 요청 여부를 추정하지 않는다.
- 숨겼을 때 애니메이션 프레임과 무작위 동작 계산을 중단한다. 숨김으로 시작하면 캐릭터 WebGL 초기화도 첫 표시까지 미룬다. 다시 보일 때 위치와 초안을 복원하며, 이미 본 시작 연출을 반복하지 않는다.
- 숨김이 RAM·서버 CPU·외부 AI GPU 사용을 0으로 만든다고 안내하지 않는다. 절감 대상은 캐릭터 렌더링이며, 메모리 서비스는 사용자가 바라를 종료할 때까지 유지된다.
- 종료는 신규 요청 접수를 멈추고 진행 요청을 정리한다. 제안 기본값은 최대 15초 대기 후 소유 프로세스를 종료하는 것이다. 확인되지 않은 저장은 기존 요청 ID·초안을 남기고 다음 실행에 확인하며 자동 재전송하지 않는다. 종료가 끝나기 전까지 트레이를 유지한다.

## 4. 설치·연결 자동화 범위

### 4.1 이 컴퓨터

기존 설치·포트·저장 공간·모델 준비 상태를 확인하고 현재 설치 관리자와 복구 기록을 재사용한다. 기존 데이터가 발견되면 새로운 빈 DB로 바꿔 연결하지 않는다. 다운로드 용량과 진행 상태, 실패한 단계와 다시 시도할 조작을 보여준다. 새 설치의 대시보드 관리자 자격과 펫 일상용 자격은 지금처럼 분리해 보관한다.

연결 확인은 읽기 작업으로 수행한다. 처음 메모를 남겨보는 안내는 사용자가 입력할 때만 저장하며, 테스트 메모를 몰래 만들거나 남기지 않는다.

### 4.2 사용 중인 바라 연결

대시보드에서 연결을 시작하고 앱에서 짧은 코드 또는 일회용 링크를 사용하는 흐름을 추가한다. 처음 연결하는 서버에는 **서버 주소+코드**, 또는 서버 주소가 포함된 일회용 링크를 사용한다. 이미 저장된 서버는 주소를 고른 뒤 코드만 입력한다. QR은 같은 일회용 링크를 표시하는 편의 수단이며, 카메라 권한이나 새 라이브러리 없이 가능한 방법을 먼저 검토한다. 짧은 코드만으로 임의 서버의 위치를 찾는 외부 중계 서비스는 만들지 않는다. SSH 연결은 먼저 확인한 터널을 사용하고, 다른 PC의 localhost 주소를 그대로 유효한 서버 주소로 취급하지 않는다.

새 서버 계약에는 다음 조건을 넣는다.

- 기존 `/adapter-enroll` 승인 구조를 재사용하되, 만료·일회 연결·대상 확인을 실제로 구현한다. 지금 이미 있는 기능으로 간주하지 않는다.
- 제안 기본값: 5분 유효, 8자리 연결 코드, 연결별 실패 5회 제한과 서버 측 요청 속도 제한. 링크에는 충분히 긴 무작위 비밀값을 사용한다. 코드·링크는 장기 관리자 토큰이 아니다.
- 한 코드가 바인딩하는 설치는 하나다. 승인 대상의 기기 이름·서버 주소를 양쪽에서 확인한다.
- “일회용”은 연결을 한 기기에 한 번 귀속한다는 뜻이다. 같은 기기의 저장된 회수 증명으로 재시도하면 응답 유실 뒤에도 같은 발급 결과를 회수할 수 있어야 한다. 다른 기기의 재사용은 거절한다.
- 설치별 안정적인 식별자를 사용해 두 PC의 요청이 서로 취소되지 않게 한다. 기존 `pet`/`bara-pet` 자격을 업그레이드만으로 폐기하지 않는다.
- 펫 일상용 권한과 대시보드 관리 권한을 구분한다. 관리 권한은 소유자가 `이 PC에서 대시보드 관리 허용`을 승인한 경우에만 별도로 전달·보관한다. 장기 관리자 자격을 QR·진행 로그·화면 설정·외부 AI 앱에 넣지 않는다.
- HTTPS 또는 검증된 SSH 통로/로컬 연결을 사용한다. 전달받은 링크가 임의 명령 실행·새 서버 설치·설정 파일 쓰기를 직접 유발하지 않게 한다.
- 구버전 서버에는 기존 연결 링크·승인 방식으로 이어갈 수 있는 안내를 제공한다. 사용자 요청 없이 운영 서버를 업그레이드하지 않는다.

### 4.3 SSH와 외부 신규 설치

사용자는 서버 주소·계정과 사용할 키를 선택한다. 앱은 OpenSSH 준비, 키 존재·형식·접근 권한, 연결 상태, 전달 포트 소유권을 확인한다.

- WSL 키는 배포판과 파일을 사용자가 선택한 뒤 앱 전용 Windows 폴더로 가져온다. 원본을 삭제하거나 원본 권한을 바꾸지 않는다.
- 가져온 사본에만 현재 사용자 중심의 제한된 접근 권한을 적용한다. 개인키 내용은 UI·로그·명령 인자로 출력하지 않는다.
- 암호가 있는 키는 사용자 SSH 에이전트 준비 흐름을 안내한다. 키 암호를 일반 설정 파일에 저장하지 않는다.
- 서버 지문 확인을 유지한다. 바뀐 지문은 자동으로 받아들이지 않는다.
- 포트가 사용 중이면 앱이 관리하는 다른 포트를 확보하고, 저장된 연결 신원·인증정보를 함께 갱신한다. 다른 프로세스가 연 포트에 인증정보를 보내지 않는다.
- 인증 실패·키 권한·주소 오류·포트 충돌을 구분해 안내한다. 현재처럼 모두 “터널 포트를 열지 못함”으로 뭉뚱그리지 않는다.
- 외부 신규 설치는 기존 “내 외부 서버” 경로를 개선한다. 클라우드 계정·인스턴스 생성과 기존 서버 덮어쓰기는 포함하지 않는다.

### 4.4 답변 AI와 정리 AI

알려진 로컬 주소와 설치된 실행 프로그램을 제한된 범위에서 확인한다. 전체 네트워크나 디스크를 무차별 탐색하지 않는다. 여러 후보가 있으면 목록에서 선택하고, 고급 주소·모델명 입력은 접어 둔다.

- 답변 AI와 정리 AI는 각각 검사한다. 저장 완료와 실제 연결 성공을 구분한다.
- 모델 목록을 선택 UI로 제공한다. 후보가 여러 개면 사용자가 선택한다. AI가 없어도 저장·검색은 사용할 수 있다.
- 로그인되지 않은 CLI는 로그인 안내를 표시한다. 다른 계정에 자동 로그인하거나 자격을 구매하지 않는다.
- AI 프로그램·대형 답변 모델을 몰래 설치하지 않는다. 필요하면 별도 설치 안내를 제공한다.
- 펫의 답변·정리 설정을 바꿨다고 서버의 추출·비전 모델 설정까지 임의로 바꾸지 않는다.
- AI 정리는 제안을 만들며, 실제 기억 변경 승인은 사용자에게 남긴다.

### 4.5 MCP 자동 연결

첫 지원 대상은 현재 설정 출력 도구가 다루는 Codex와 Claude Code로 한정한다. 설치된 버전의 공식 등록 방법·설정 위치·stdio 지원을 확인한 뒤 지원 판정을 한다. 다른 앱과 알 수 없는 설정 형식은 자동 변경하지 않고 설정 예시를 제공한다.

**기술 제안:** 외부 AI 앱에는 비밀값 없는 실행 명령과 연결 ID를 등록한다. 얇은 stdio 연결기가 실행 중인 바라 앱의 현재 사용자 전용 IPC로 요청을 전달하고, 바라 내부에서 그 외부 앱 전용 제한 토큰으로 기존 `/mcp`에 접근한다.

- 연결기는 독립 메모리 서버가 아니다. 바라가 꺼져 있으면 `바라를 먼저 실행해 주세요`라는 연결 상태를 반환한다. 메모리 엔진을 혼자 띄우거나 바라를 몰래 재실행하지 않는다.
- 전역 평문 환경변수나 외부 앱 설정 파일에 장기 토큰을 저장하지 않는다. 관리자 토큰·복호화 API를 외부 앱에 제공하지 않는다.
- IPC는 현재 Windows 사용자와 승인된 연결 ID로 제한한다. 가능한 요청은 정해진 MCP 전달 요청뿐이며, 크기·시간·동시 요청 수를 제한한다. 서버 주소를 호출자가 임의로 바꿀 수 없게 한다.
- 인증정보 저장은 현재 고정 키 4개를 넘어 외부 앱별 제한 자격을 보관하는 명시적 계약이 필요하다. 기존 자격은 유지하며 재등록·해제·서버 변경을 구분한다.
- 사용자가 외부 AI 앱 연결을 선택하면 설치 ID·통합 ID로 그 앱의 등록을 별도로 신청하고 `mcp-standard` 권한을 발급받는다. 펫 일상 토큰이나 관리자 토큰을 복사해 대신 쓰지 않는다. 바라에 관리 자격이 있으면 그 특정 요청만 승인하고, 없으면 대시보드에서 소유자가 승인하도록 기다린다.
- 앱별 요청 ID와 회수 증명을 비공개로 보관하여 중단·재실행 뒤 같은 등록을 이어간다. 승인 거절·만료·회수 실패는 각각 표시하며 승인 대기를 연결 완료로 표시하지 않는다.
- 자동 등록은 사용자가 선택한 앱의 Bara 항목만 변경한다. 백업, 동시 수정 감지, 원자적 저장과 복구를 포함한다. 다른 MCP 항목과 사용자가 작성한 설정을 보존한다.
- 연결 확인은 도구 목록과 읽기 호출로 한다. 메모리를 추가하거나 정리 제안을 승인하지 않는다.
- 실제 메모리 서버 포트는 자동 선택될 수 있다. 외부 앱에 고정 `3001`을 가정하지 않고, 연결기가 현재 바라의 검증된 연결을 사용한다.

### 4.6 선택적 Discord

첫 설치의 필수 단계로 만들지 않는다. 사용자가 선택하면 기존 봇 코드를 준비하고 인증정보 확인, 바라 등록, 채널 선택, 실행 확인을 연결한다.

- Discord 계정 로그인·앱/봇 생성·서버 초대 및 권한 승인은 사용자 단계다. 공식적으로 가능한 범위만 안내·자동화하며 현재 없는 API를 가정하지 않는다.
- 제공받은 Discord 자격은 앱의 비밀 저장소에 넣고 소유한 봇 프로세스에만 전달한다. 공개 설정·로그에 남기지 않는다.
- 앱이 띄운 봇은 바라와 함께 실행·종료한다. 외부에서 이미 실행 중인 봇을 임의로 종료하거나 중복 실행하지 않는다.
- 바라 등록에 필요한 실제 권한을 확인하고 표시한다. 현재 봇이 요청하는 권한을 근거 없이 축소하거나 관리 권한을 숨겨 설명하지 않는다.
- 연결 해제는 해당 봇의 앱 소유 실행과 등록을 정리한다. 사용자의 Discord 앱·서버·기억은 삭제하지 않는다.

### 4.7 버전 확인과 데이터 보존 업데이트

**기본 정책:** 프로그램 파일 묶음을 새 버전으로 맞추고, 기억·첨부·모델·설정·인증정보·초안을 이어 사용한다. 프로그램 폴더를 통째로 지우는 것을 데이터 정리 방법으로 사용하지 않는다.

- 앱 버전, 설치 payload의 버전/파일 목록, DB 스키마 버전, 설정 형식 버전을 구분한다. 배포마다 앱 버전을 올리고 `package.json`·Tauri·Cargo·표시 버전의 불일치를 빌드에서 거절한다. 앱 식별 정보와 설치 등록 키는 유지하며, 변경이 필요하면 이전 설치를 찾는 전환 절차를 둔다.
- 이전 버전→새 버전은 업데이트, 같은 버전은 복구/재설치로 구분한다. 더 오래된 앱으로의 일반 설치는 기본 차단한다. 호환되지 않는 DB를 빈 DB로 바꾸어 실행하지 않는다.
- 새 프로그램을 임시 위치에 준비하고 파일 목록·무결성·필요 공간을 먼저 확인한다. 기존 설치 목록과 새 목록의 차이로 폐기된 앱 소유 파일을 제거하며, 목록에 없는 사용자 파일은 삭제하지 않는다. 덮어쓰기만으로 옛 파일이 모두 정리됐다고 간주하지 않는다.
- 진행 중 입력을 정리하고 앱 소유 서버·봇·터널을 멈춘 뒤 일관된 복구 지점을 만든다. SQLite의 WAL을 누락한 단순 파일 복사는 백업으로 인정하지 않는다. DB·설정·암호화 자격·초안·자동 실행 및 외부 연결 등록의 복원 정보를 함께 관리한다.
- **백업은 최초 DB 변경보다 먼저 완료·검증한다.** 서버 시작 경로뿐 아니라 `managed-prepare`의 DB 열기에서도 백업 전에 마이그레이션이 실행되지 않도록 공통 경계를 둔다. 백업 실패·공간 부족이면 기존 설치를 변경하기 전에 중단한다.
- 프로그램 교체 뒤 필요한 DB/설정 변환을 수행하고 읽기 중심의 시작 검사를 한다. 그동안 사용자·MCP·봇 입력과 자동 정리 등 새 쓰기를 받지 않는 유지보수 상태를 유지한다. 검사 성공 후 정상 사용을 허용한다.
- 정상 사용을 허용하기 전 실패하면 기존 DB를 바꾸지 않은 채 중단하거나, 아래 4.7.1의 글 형식 백업으로 복구하도록 안내한다. 이전 프로그램과 DB를 한 쌍으로 자동 되돌리는 장치는 두지 않는다. 새 버전에서 사용자 쓰기를 받기 시작한 후에는 과거 백업으로 자동 되돌려 새 기억을 잃게 하지 않는다. 이 경우에는 데이터를 보존한 복구 안내를 제공한다.
- 업데이트는 제거와 구분한다. 자동 실행 여부, 펫/트레이 모드, 연결 식별자와 토큰, 외부 AI 앱의 등록을 유지한다. 이전 제거 프로그램을 거치는 경로에서도 현재의 무조건적인 자동 실행 삭제 훅 때문에 선택이 사라지지 않게 보존·복원한다.
- 업데이트 단계와 완료 여부를 기록해 중단·재실행 시 어느 단계에서 멈췄는지 판단한다. 설치 파일을 직접 실행하는 업데이트부터 검증하며, 새 버전을 찾아 내려받는 자동 업데이트 배포 서비스까지 구현된 것으로 취급하지 않는다.

#### 4.7.1 글 형식 백업과 복원 전용 가져오기 (2026-10-04 사용자 결정)

**결정:** 업데이트 실패 복구의 중심 수단을 "프로그램과 DB를 한 쌍으로 자동 되돌리는 장치"에서 **DB 구조와 무관한 글 형식 내보내기 + 복원 전용 가져오기**로 바꾼다. 같은 기능이 임베딩 모델 교체 때 기존 기억을 옮기는 통로를 겸한다(현재는 모델의 차원이 바뀌면 빈 DB로 다시 시작해야 해서 기존 기억을 가져갈 길이 없다).

**복구 수단 두 가지의 역할**

| 수단 | 용도 | 한계 |
|---|---|---|
| 기존 DB 스냅샷(P4 서버 내장 백업, 파일 복사 방식) | 같은 버전으로 빠르게 되돌리기 | 새 형식 DB를 옛 프로그램이 읽지 못한다. 모델 차원이 바뀌면 쓸 수 없다 |
| 글 형식 내보내기(신규) | 버전·모델과 무관한 복구, 다른 PC로 이전, 모델 교체 | 다시 넣을 때 임베딩 재계산 시간이 든다 |

**흐름**

- 업데이트 직전: DB 스냅샷과 글 형식 내보내기를 둘 다 만들고, 내보낸 파일을 다시 읽어 개수·형식을 검증한 뒤에만 진행한다. 어느 하나라도 실패하면 기존 설치를 바꾸기 전에 중단한다.
- 업데이트 실패: 새로 설치(새 버전 또는 이전 버전)한 빈 DB에 내보낸 파일을 가져와 복구한다.
- 모델 교체: 내보내기 → 새 모델 설정으로 빈 DB 시작 → 가져오면서 새 모델로 임베딩 재계산.

**요구 조건**

- **무손실:** 본문뿐 아니라 만든 시각·마지막 접근 기록·중요도·종류·태그·작성자, 기억 사이 관계와 별칭, 휴지통 상태, 첨부 이미지 원본을 모두 담는다. 빠지면 기억은 돌아와도 검색 순위(최신성·중요도·관련도 가중)가 초기화된다. 무엇을 담는지는 구현 전에 DB 테이블 기준 전수 목록으로 확정한다.
- **복원 전용 가져오기:** 평소 저장 경로의 저장 게이트·중복 병합·충돌 검사를 거치지 않고 원본 그대로 넣는다. 평소 경로를 쓰면 비슷한 기억이 합쳐지거나 거절돼 개수가 달라진다. 가져온 뒤 원본과 개수·관계 수를 대조해 결과를 표시한다.
- **형식 버전:** 내보낸 파일에 형식 버전을 기록하고, 새 프로그램은 옛 형식 파일도 계속 읽는다. 알 수 없는 새 형식은 거절한다.
- **임베딩 값:** 선택적으로 함께 담는다. 가져올 때 모델 이름과 차원이 같으면 재사용하고, 다르면 버리고 재계산한다.
- **처리량:** 재계산 속도를 실제 PC에서 측정해 기억 수별 예상 시간을 안내한다. 진행률을 표시하고, 중단되면 이어서 가져올 수 있게 한다.
- **비밀값 제외:** 토큰·개인키 같은 자격은 글 형식 파일에 넣지 않는다. 자격은 기존 암호화 보관 경로로만 유지한다.
- **위치:** 내보내기·가져오기는 메모리 서버(`apps/memory`) 기능으로 구현해 A1 서버와 펫 모두 같은 형식을 쓴다.

**약점(결정 시 인지한 대가)**

- 기억이 많으면 복구·모델 교체에 수십 분이 걸릴 수 있다(기억 1개당 0.1초 가정 시 1만 개 약 17분, 실측 필요).
- 형식 변경 문제가 사라지는 것이 아니라 DB 구조에서 내보내기 형식으로 옮겨간다. 다만 내보내기 형식은 DB 구조보다 단순하고 자주 바뀌지 않는다.
- 무손실 목록에서 빠진 항목은 복구 때 조용히 사라진다. 새 테이블·필드를 추가할 때 내보내기 대상인지 함께 결정해야 한다.

**Obsidian 내보내기와의 관계:** `docs/design-considerations.md`의 "Obsidian 호환 폴더 자동 내보내기"는 사람이 보고 편집하는 보기용이라 정보가 일부 빠져도 되는 반면, 이 형식은 무손실 복원용이다. 이 글 형식을 원본으로 두고 Obsidian용 md는 그 원본에서 만드는 후속 기능으로 둔다. Obsidian에서 고친 md를 복원 경로로 받지 않는다.

### 4.8 제거 범위와 완료 표시

기본 선택은 **프로그램만 제거**다. **이 PC에서 완전히 제거**는 삭제할 데이터 종류·경로·용량과 복구할 수 없다는 점을 표시한 뒤 명시적으로 선택·확인하게 한다. 사용자가 별도로 내보낸 백업은 두 모드 모두 지우지 않는다.

| 항목 | 프로그램만 제거 | 이 PC에서 완전히 제거 |
|---|---|---|
| 앱 소유 프로세스·실행 파일·동봉 런타임·서버/봇 코드 | 종료 후 제거 | 종료 후 제거 |
| 바로가기·설치 등록·자동 실행·앱이 등록한 프로토콜 | 제거 | 제거 |
| 이 PC의 기억 DB·첨부·모델·설정·토큰·초안·앱 내부 백업 | 보존하고 위치 안내 | 확인한 앱 소유 데이터만 제거 |
| 앱이 자동 추가한 외부 AI 앱의 활성 MCP 항목 | 제거하고 재설치용 등록 의도는 보존 | 제거 |
| 서버에 발급한 앱/통합 자격 | 재설치용으로 보존; 현재 연결은 종료 | 소유권을 확인한 이 설치의 자격만 폐기 시도 |
| A1 등 외부 서버의 기억·공용 데이터·다른 앱의 AI/봇·원본 SSH 키·직접 내보낸 백업 | 유지 | 유지 |

- 기본 NSIS의 데이터 삭제 체크박스를 그대로 완전 삭제 기능으로 쓰지 않는다. 실제 `%LOCALAPPDATA%\Bara\Pet`와 등록된 사용자 데이터 위치를 대상으로 한 명시적인 절차를 만든다.
- 삭제 대상을 프로그램 영역·앱 소유 데이터·앱 소유 외부 등록으로 나누어 기록한다. 환경변수나 설정에 적힌 경로만으로 폴더 전체를 앱 소유라고 판단하지 않는다. 사용자 지정 경로와 레거시 설치는 실제 소유 근거를 확인하고, 불명확한 파일은 보존해 남은 항목으로 알린다.
- 삭제 전 최종 절대 경로와 소유 범위를 검사한다. 드라이브 루트·사용자 홈·공유 폴더 전체를 지우거나 심볼릭 링크/정션을 따라 범위 밖 데이터를 지우지 않는다. 앱 소유로 확인한 디렉터리의 링크는 대상에 진입하지 않고 링크 자체만 처리한다.
- MCP 등록은 앱이 관리한 연결 ID와 마지막 기록을 대조하여 해당 항목만 지운다. 사용자가 바꾼 항목이나 다른 MCP 설정을 덮어쓰거나 과거 설정 파일 전체로 복원하지 않는다.
- 외부 자격 폐기는 필요한 자격과 도구가 아직 있는 동안 실행하고, 그 뒤 로컬 자격·데이터·프로그램을 제거한다. 공유 중이거나 소유권이 불명확한 레거시 토큰을 임의로 폐기하지 않는다.
- 원격 서버가 오프라인이거나 권한이 없으면 로컬 제거와 원격 해제 결과를 구분한다. 사용자가 로컬 완전 제거를 계속하면 재시도를 이유로 비밀값이나 숨겨진 작업을 남기지 않는다. 화면에 남은 원격 등록과 직접 해제할 방법을 알리고, 복구 기록 내보내기는 사용자가 선택할 때만 한다.
- 파일 잠금·외부 설정 충돌 등으로 일부 항목이 남으면 남은 경로와 이유, 재시도/재부팅 필요 여부를 보여준다. 확인하지 못한 상태를 “완전히 제거됨”으로 표시하지 않는다.
- 제거 후 앱 소유 서버·봇·터널·연결기가 다시 살아나지 않아야 한다. 다른 앱의 실행 환경, Windows 공용 WebView2, 외부 서버는 제거 대상이 아니다.

## 6. 범위 밖

독립 메모리 데몬·Windows 서비스, 클라우드 계정/인스턴스 자동 생성, 공유 다중 사용자 인증 서비스, 자율 포스팅·댓글, 다른 플랫폼 어댑터 신규 작성, 사용자 승인 없는 데이터 전송·정리 적용은 포함하지 않는다. **운영 중인** 원격 서버의 무인 업데이트·새 버전 자동 배포와 기존 운영 DB 이관은 별도 요청 대상이다. 사용자가 선택한 **비어 있는 외부 서버의 최초 설치**는 4.3절의 포함 범위다.

실행 순서·파일 범위·검증 기준은 [실행 계획](2026-10-04-onboarding-tray-plan.md)을 따른다.
