# 바라시스템 입력 안내서 — 엔티티 종류별 칸·태그 사용법

바라시스템은 입력한 글을 기억으로 저장하고, 그 안에 등장한 **사람·작품·일정·장소** 같은 대상을 자동으로 골라내 검색할 수 있게 정리하는 메모리 모듈입니다.

대상을 더 또렷하게 알려주고 싶을 때 **해시태그**(`#키:값` 형태)를 함께 적습니다. 이 안내서는 각 종류에 어떤 태그를 쓰는지 정리합니다. 여기 적힌 태그·칸은 전부 실제 코드(`src/db/schema/` 기준 스키마 SQL·어휘 사전·태그 처리기)로 확인된 것만 담았습니다.

---

## 1. 입력 기본 양식

### 1-1. 그냥 글만 써도 됩니다

해시태그 없이 평범하게 글을 적어도 저장·검색됩니다. 해시태그는 "이 대상을 이렇게 기억해 줘"라고 더 정확히 알려주는 보조 수단입니다.

### 1-2. 해시태그는 `#키:값` 형태

```
#키:값
```

- **콜론(`:`) 뒤의 값이 그 대상의 이름**입니다. 예: `#작품:괴담` 은 "괴담이라는 이름의 작품"을 뜻합니다.
- 반대로 `#작품:소설` 처럼 적으면 안 됩니다. 콜론 뒤에는 **종류 단어("소설")가 아니라 실제 이름**이 와야 합니다.
- 종류와 이름을 함께 알려주고 싶으면 두 태그를 이어 적습니다(콜론 사슬):
  ```
  #작품:소설 #소설:괴담
  ```
  이렇게 적으면 "소설이라는 종류 아래, 괴담이라는 작품"으로 위계까지 함께 정리됩니다.

### 1-3. 키 글자(콜론 앞)가 처리 방식을 가릅니다

같은 `#키:값` 형태라도 키 글자에 따라 처리가 갈립니다.

- **종류 키**(`#사람:` `#작품:` `#일정:` 등) — 그 종류의 대상을 만들고, 값이 이름이 됩니다.
- **칸 키**(`#생일:` `#유통기한:` `#주소:` 등) — 그 대상의 정해진 칸(고정 정보)을 채웁니다.
- **라벨 키**(`#직업:` `#장르:` `#언어:` 등) — 여러 대상이 공유하는 특성을 붙입니다.
- **관계 키**(`#가족:` `#작가:` `#주인:` 등) — 한 대상을 다른 대상과 이어 줍니다.
- **알 수 없는 키** — 위 어디에도 없으면 조용히 무시하지 않고 건너뛴 사유를 남깁니다(잘못 채워 넣지 않습니다).

---

## 2. 칸과 라벨의 차이

- **칸(고정 정보)** — 한 대상 고유의 사실. 사람의 생일, 일정의 날짜처럼 그 대상에만 해당하는 값. DB 의 전용 칸에 들어갑니다.
- **라벨(공유 특성)** — 여러 대상이 함께 가질 수 있는 특성. 사람의 직업, 작품의 장르처럼 같은 값을 여러 대상이 공유할 수 있는 것. 검색으로 같은 라벨끼리 묶입니다.

> 어떤 키가 칸인지 라벨인지는 종류마다 정해져 있습니다(아래 표). 정해진 칸 키만 칸에 들어가고, 나머지는 라벨로 처리됩니다.

---

## 3. 엔티티 종류별 칸·태그 표

엔티티는 **사람 · 프로젝트 · 생물 · 사물 · 섭취 · 사용물 · 작품 · 자료 · 장소 · 일정** 열 종류입니다.

### 3-1. 사람

| 항목 | 내용 |
|---|---|
| 선언 태그 | `#사람:이름` |
| 전용 칸 | `birthday`(생일) · `address`(주소) · `gender`(성별) |
| 칸 태그 | `#생일:` · `#주소:` · `#성별:` |
| 별칭 태그 | `#닉네임:` · `#별명:` |
| 라벨 태그 | `#직업:` · `#회사:` (그리고 자유 라벨) |
| 관계 태그 | `#관계:` (관계 종류를 알려주는 지붕) · `#가족:` · `#친구:` |

- 생일·주소·성별은 그 사람 고유 사실이라 **칸**입니다.
- 직업·회사는 여러 사람이 공유할 수 있어 **라벨**입니다.
- `#가족:엄마` 처럼 적으면 사람 사이를 "가족" 관계로 잇습니다. `#친구:` 도 마찬가지입니다.
- 칸 태그(생일 등)는 한 글에 사람이 여럿이면 누구 것인지 모호해 아무에게도 안 붙고 경고가 나옵니다. 라벨(직업 등)은 적힌 모든 사람에게 붙습니다.

### 3-2. 프로젝트

| 항목 | 내용 |
|---|---|
| 선언 태그 | `#프로젝트:이름` (동의어 `#작업:` `#작업물:` 도 같은 종류) |
| 전용 칸 | 없음 |
| 라벨 태그 | `#언어:` · `#엔진:` (그리고 자유 라벨) |
| 관계 태그 | `#참여자:` (그 프로젝트에 참여한 사람) |
| 하위 분류 | 코딩 · 그림 · live2d · 작곡 · 글쓰기 |

- 프로젝트 전용 칸은 없습니다. 사용 언어·엔진은 라벨로 붙습니다.
- `#참여자:이름` 은 프로젝트와 사람을 이어 줍니다.

### 3-3. 생물 (동물·식물·반려동물)

| 항목 | 내용 |
|---|---|
| 선언 태그 | `#생물:이름` (동의어 `#creature:`) |
| 전용 칸 | 없음 |
| 라벨 태그 | `#종류:` (그리고 자유 라벨) |
| 관계 태그 | `#주인:` (그 생물의 주인 사람) |
| 하위 분류 | 동물 · 식물 · 반려동물 |

- `#동물:고양이` 처럼 종류를 적으면 "생물 > 동물 > 고양이" 위계로 정리됩니다.

### 3-4. 사물 (만질 수 있는 물건)

| 항목 | 내용 |
|---|---|
| 선언 태그 | `#사물:이름` (동의어 `#물건:`) |
| 전용 칸 | 없음 |
| 라벨 태그 | `#종류:` (그리고 자유 라벨) |

### 3-5. 섭취 (먹고 마시는 것)

| 항목 | 내용 |
|---|---|
| 선언 태그 | `#섭취:이름` |
| 전용 칸 | `expires_at`(유통기한) |
| 칸 태그 | `#유통기한:` |
| 라벨 태그 | `#종류:` (그리고 자유 라벨) |
| 관계 태그 | `#관련사람:` |
| 하위 분류 | 음식 · 음료 · 식재료 |

### 3-6. 사용물 (써서 닳거나 사용하는 물건)

| 항목 | 내용 |
|---|---|
| 선언 태그 | `#사용물:이름` |
| 전용 칸 | `usage_condition`(사용조건) · `usage_method`(사용방식) |
| 칸 태그 | `#사용조건:` · `#사용방식:` |
| 라벨 태그 | `#대상부위:` · `#위험요소:` · `#보관방법:` (그리고 자유 라벨) |
| 관계 태그 | `#관련사람:` |
| 하위 분류 | 약 · 화장품 · 도구 |

### 3-7. 작품 (창작물)

| 항목 | 내용 |
|---|---|
| 선언 태그 | `#작품:이름` (동의어 `#창작물:`) |
| 전용 칸 | 없음 (이름·매체·작가 조합으로 같은 작품 구분) |
| 라벨 태그 | `#유형:` · `#장르:` (그리고 자유 라벨) |
| 관계 태그 | `#작가:` · `#창작자:` · `#제작자:` · `#만든사람:` (네 키 모두 "작품을 만든 사람"으로 이어짐) |
| 하위 분류 | 소설 · 만화 · 게임 · 애니 · 영화 · 음악 · 웹툰 |

- 작품에 작가를 적으면, 그 작가의 다른 작품도 검색에 함께 딸려 나옵니다.

### 3-8. 자료 (참고·학습 자료)

| 항목 | 내용 |
|---|---|
| 선언 태그 | `#자료:이름` |
| 전용 칸 | 없음 |
| 라벨 태그 | `#주제:` (그리고 자유 라벨) |
| 관계 태그 | `#출처:` (그 자료의 출처 — 사람·작품·자료) |
| 하위 분류 | 문서 · 논문 · 회의록 · 교재 · 코드 · 데이터 |

### 3-9. 장소

| 항목 | 내용 |
|---|---|
| 선언 태그 | `#장소:이름` (동의어 `#공간:`) |
| 전용 칸 | `address`(주소) |
| 칸 태그 | `#주소:` |
| 라벨 태그 | `#실제:` · `#가상:` (그리고 자유 라벨) |

### 3-10. 일정 (시간 약속·예정)

| 항목 | 내용 |
|---|---|
| 선언 태그 | `#일정:이름` (동의어 `#약속:` `#기한:`) |
| 전용 칸 | `event_at`(예정 시각) |
| 칸 태그 | `#날짜:` |
| 라벨 태그 | `#종류:` (그리고 자유 라벨) |
| 관계 태그 | `#관련사람:` · `#관련장소:` |

## 4. 예시 입력

### 예시 1 — 사람 등록

```
#사람:성춘향 #관계:가족 #생일:1990-03-15 #성별:여 #주소:서울
```

성춘향을 가족 관계의 사람으로 등록하고, 생일·성별·주소 칸을 채웁니다.

### 예시 2 — 작품과 작가

```
#작품:소설 #소설:괴담 #작가:이몽룡 #장르:공포
```

"소설 > 괴담" 위계로 작품을 정리하고, 작가로 이몽룡을 잇고, 장르 라벨로 공포를 붙입니다. 나중에 이몽룡의 다른 작품을 검색하면 괴담도 함께 나옵니다.

### 예시 3 — 일정

```
오늘 이몽룡이랑 회의했다. #일정:기획회의 #날짜:2026-07-01 #관련사람:이몽룡
```

기획회의라는 일정을 만들고 예정 시각 칸을 채운 뒤, 관련 사람으로 이몽룡을 잇습니다.

### 예시 4 — 섭취 (유통기한)

```
#섭취:우유 #유통기한:2026-06-25 #종류:음료
```

우유를 섭취 대상으로 만들고 유통기한 칸을 채운 뒤, 음료 라벨을 붙입니다.

### 예시 5 — 친구 관계

```
#사람:홍길동 #친구:이몽룡 #직업:디자이너
```

홍길동을 등록하고 이몽룡과 친구 관계로 잇고, 직업 라벨(디자이너)을 붙입니다.

### 예시 6 — 프로젝트와 참여자

```
#프로젝트:프로젝트A #언어:타입스크립트 #참여자:홍길동
```

프로젝트A를 등록하고 사용 언어 라벨(타입스크립트)을 붙인 뒤, 참여자로 홍길동을 잇습니다.

---

## 5. 알아두면 좋은 규칙

- **콜론 뒤는 항상 이름**입니다. 종류를 알려주려면 `#작품:소설 #소설:괴담` 처럼 사슬로 적습니다.
- **정해진 칸 태그만 칸에 들어갑니다.** 표에 없는 키는 라벨로 처리되거나(공유 특성), 알 수 없는 키면 건너뜁니다.
- **칸을 비워 두는 게 정직합니다.** 모르는 값을 지어내지 않습니다. 안 적은 칸은 빈 채로 남습니다.
- 같은 칸 정보(생일 등)는 한 글에 사람이 여럿이면 모호해서 안 붙고 경고가 납니다. 한 사람씩 따로 적어 주세요.

> 종류별 하위 분류 단어(소설·동물·음료 등)와 라벨 키는 어휘 사전(`apps/memory/src/memory/concept_type_vocabulary.yaml`)에서 직접 보태고 고칠 수 있습니다.
