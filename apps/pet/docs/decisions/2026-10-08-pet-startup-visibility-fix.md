# 자동 실행 직후 펫 이미지가 보이지 않는 문제

## 증상과 재현

설치 완료 후 실행하거나 Windows에 로그인해 자동 실행하면 펫 이미지가 보이지 않았다. 그 위치를 클릭하면 입력창은 열렸고, 트레이에서 숨겼다가 다시 보이면 이미지가 나타났다.

Windows release 실행 파일을 별도 `BARA_PET_DATA_DIR`로 두 차례 실행해 같은 상태를 재현했다. WebView2 진단에서 실제 창과 문서는 보이는 상태였지만, 화면의 `HostVisibility`는 `known=false, events=0`, `RendererPresence`는 `waiting`이었다. 캔버스는 기본 크기 300×150으로 남았고 Spine 그림 파일을 요청하지 않았다. 숨기지 않고 표시 명령만 다시 보내도 파일을 읽고 그림이 나타났다.

펫 창은 숨긴 상태로 먼저 만들어진다. 다른 창을 생성하는 동안에도 펫 페이지가 실행될 수 있어 `get_pet_visible`이 초기 HWND의 숨김 상태를 반환했다. 시작 표시 이벤트를 받지 못하면 이 값이 계속 남아 캐릭터 생성이 시작되지 않았다. 이미지 파일이나 GPU 렌더링 실패가 아니었다.

## 수정

- `src-tauri/src/app_visibility.rs`: 호스트가 요청한 표시 상태를 보관하는 `PetVisibility`를 추가했다.
- `src-tauri/src/main.rs`: 저장된 표시 모드를 **첫 창을 만들기 전에** 읽어 상태를 등록한다. 펫 페이지의 초기 조회는 이 상태를 반환한다.
- `src-tauri/src/tray.rs`: 표시·숨김 요청은 네이티브 창 조작 전에 상태부터 갱신한다. 창 조작 도중 조회해도 최신 값을 받는다.

초기 조회와 이후 이벤트가 같은 상태를 사용한다. 타이머나 반복 조회를 추가하지 않았다. 펫 창만 초기 조회를 할 수 있는 권한 검사, 실제 창 상태를 기준으로 한 트레이 토글·창 위치·말풍선 처리, 한 표시 단계가 실패해도 나머지를 시도하는 동작은 유지한다. Alt+F4 숨김도 기존의 공통 표시 경로를 사용한다.

## 검증

- 수정 전 실제 release 실행에서 캐릭터 로드 검사 실패를 확인했다.
- 수정 후 실제 release/WebView2에서 첫 실행과 저장된 `pet` 모드 재실행 모두 별도 조작 없이 그림이 나타났다. 초기 표시 이벤트를 받지 않은 상태(`events=0`)에서도 `known=true`, 렌더러 `running`, 캔버스 225×249(150% 배율), Spine 애셋 로드를 확인했다.
- 저장된 `tray` 모드로 재실행하면 숨김 상태를 유지하고 캐릭터 애셋을 읽지 않았다. 표시 명령을 보내면 그림이 나타났다.
- `bun test src tests`: **830 pass / 0 fail / 2 skip**. 생략한 두 검사는 모델 미지정 상태의 선택적 실제 AI 평가다.
- `cargo test --manifest-path src-tauri/Cargo.toml`: **120 pass / 0 fail**. 초기 표시 상태와 이벤트 없는 숨김·표시 검사 두 개를 추가하고, 각 네이티브 단계·실패 중 재진입 조회 검사를 보강했다.
- 타입 검사, UI 빌드, Rust 포맷, `cargo clippy --tests -- -D warnings`, 독립 코드 검토 통과.
- `bun run build`: 서비스/UI/release/NSIS 빌드와 Windows GUI 실행 파일 검사(`subsystem=2`) 통과. 일반 release 빌드에는 기존 `native_host.rs`의 미사용 필드 경고 두 개가 남아 있으며, 테스트를 포함한 엄격 Clippy는 통과했다.
- `graphify update .` 완료. 그래프 크기로 HTML 생성은 생략됐으며 JSON과 보고서는 갱신됐다.

진단 자료는 로컬 `apps/pet/.omx/startup-visibility-diagnostic/`에 있다. 테스트 프로세스는 종료했다. 사용자의 실행 중인 설치판과 운영 데이터는 바꾸지 않았다.

## 확인 범위

실제 Windows 실행 파일의 초기 실행 경합을 재현하고 수정 후 확인했다. OS 로그아웃·재부팅, 설치 마법사의 마지막 실행 버튼, 기존 설치판 교체는 수행하지 않았다. 이 과정까지 검증한 것으로 확대하지 않는다. 기존 미커밋 안정성 수정은 유지했고, 이번 제품 코드 변경은 위 네이티브 파일 세 개다.
